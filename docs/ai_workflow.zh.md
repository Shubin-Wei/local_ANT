# 与 AI 助手一起运行

中文 | [English](ai_workflow.md)

本文件有两类读者：想让 AI 助手（Claude Code、Codex 等）替自己跑流程的使用者，和被要求这样做的 AI 助手。

## 1. 使用者怎样开始

在仓库目录里打开 AI 助手，告诉它三件事：

```
用这个项目处理我的数据。原始数据在 /data/raw，台站表是 /data/stations.csv，结果写到 /data/result。
```

知道的话再加上：本区面波速度的大致范围、有没有仪器响应文件、仪器是不是同一型号、哪些台站野外有问题。其余的事助手按本文件去做，在需要你判断的地方停下来问你。

## 2. AI 助手的规则

1. **只用项目已有的命令**（`lant …`）。不另写处理代码，不改 `lant/` 的源码迁就数据；发现程序缺陷时停下来告诉使用者。
2. **不修改原始数据，不在仓库目录里写结果。** 所有输出都在使用者给的输出目录。
3. **判断归使用者。** `lant run all` 停在需要判断的地方（退出码 3）时，把 `records/steps/<步骤>.md` 里 “FOR YOU TO JUDGE” 的事项和要看的图交给使用者，等使用者决定。**不得自行运行 `lant confirm`**，除非使用者明确授权“这一步你看过没问题就确认”。
4. **不替使用者猜只有使用者知道的事**：仪器型号、台站的野外情况、时区、借用哪个台阵的参考曲线。
5. **不为结果好看调参数**：不放宽质控多出点，不按棋盘或残差反选正则化，不删“不好看”的台站。
6. 每个不同于默认值的参数都要有依据（数据统计、图、文献），记在 `records/decisions.md`。
7. **汇报只给数字和图**，不写“稳定”“可靠”“通过”；说明哪些没有检验、哪些受数据限制。

## 3. 谁决定什么

| | 事项 |
|---|---|
| 使用者给出 | 三个路径；知道时：速度范围、响应文件、时区、要排除的台站 |
| 程序推出，报告里写明推导 | 采样率、频带、时延窗、段长、子叠加长度、F-J 扫描范围、测量频带和速度轴、深度节点、网格、速度上下限、棋盘、剖面、色标 |
| 程序列出，使用者判断 | clean：名字歧义、坐标不一致、分量方向不明、台阵类型不明确、没有去响应且型号不明；stack：诊断候选剔不剔；reference：拾取的脊是不是基阶；inversion：起始模型、最深节点、速度上下限 |
| AI 可以自己定（记入 decisions.md） | 进程数和线程数（按核数和内存估计）；磁盘不够时不写清洗档案 |
| AI 必须先问 | 以上全部判断；`data.rename`；整台排除；借用参考曲线或起始模型；改任何质控门限或正则化；删除已有结果 |

## 4. 流程

```bash
lant check                                                   # 0. 环境；缺什么按提示装
lant run all --raw DIR --stations FILE --out OUT             # 1. 写 OUT/config.yaml 并运行
lant status -c OUT/config.yaml --json                        # 2. 每次停下之后：各步状态、原因、下一条命令
```

`lant status --json` 是唯一需要解析的接口：每一步的状态（成立、过时、等待确认、未运行、失败）、原因和 `next` 命令。循环如下：

1. 运行 `next` 给出的命令。
2. 停下后读 `OUT/records/steps/<步骤>.md` 和其中 “LOOK AT” 列出的文件（能读图就看图，不能就请使用者看）。
3. 按下表检查，向使用者汇报数字、图的位置和待判断事项。
4. 使用者决定后，执行这个决定（`lant confirm …` 或改配置），在 `decisions.md` 记一行。
5. 回到第 1 步，直到 `figures` 成立。

| 步骤 | 看什么 | 常见情况 |
|---|---|---|
| clean | 对上的台站数、无数据的台站、`coverage.png`、响应是否去除、`pulse_1s.csv` | 名字对不上：问使用者命名规则，用 `data.rename`；通道认不出：`data.channel` |
| cc | 台对数、被丢弃的段的比例、内存估计 | 内存不够：`correlation.max_distance_km` 或减小 `nproc` |
| stack | `candidates.txt`、`station_qc/station_qc.png` | 候选多于偶然期望数（1 个）时流程停下：给使用者看，由使用者决定剔不剔；只有 1 个时只在报告里列出 |
| reference | `fj.png`：脊是否连续、是不是最慢的那一支；实测速度与 `velocity_range_kms` 的比较 | 可能是高阶：说明理由，建议 `track_fundamental`、缩小速度范围或借用曲线，由使用者定 |
| disp | 接受的点数、按原因统计的拒绝数、`3_dispersion_curves.png`、`median_vs_reference.txt` | 点很少：报告是哪条判据拒的，不擅自放宽 |
| inversion | `4_start_model.png`、`4_kernels.png`、周期数、深度节点 | 周期超过求解器上限：按提示改 `per_octave` |
| run、evaluate | 预检保留比例、残差、棋盘恢复、对照差 | 主工程预检无效：停下汇报 |
| figures | 切片、剖面 | 汇报时同时给棋盘图 |

## 5. 记录

`OUT/records/decisions.md` 每个决定一行：

```
| 日期 | 步骤 | 键或事项 | 决定 | 依据 | 谁决定 |
| 2026-11-09 | stack | 候选 3 个台站子叠加 | 保留 | 相关系数只略低于门限，时移在门限内（03_stack/candidates.txt） | 使用者 |
```

确认由 `lant confirm` 写进配置文件末尾的 `confirmed:` 段；`records/` 里其余文件由程序写，不要手工改。

## 6. 出问题时

| 现象 | 做法 |
|---|---|
| 配置错误（含已删除的旧键） | 错误信息写明键和原因；按它改 |
| 某一步失败 | 读 `run_log.jsonl` 最后一条和加 `--debug` 的回溯；是数据问题就问使用者，是程序缺陷就停下汇报 |
| 状态显示过时 | 配置或上游结果变了；从 `next` 指的那一步重跑，已做的确认需要重新做 |
| 输出目录被锁 | 另一个运行还在；不要删锁文件，先确认那个进程 |
| 结果看上去不合理 | 不调参数“修好”；报告现象、数字和可能原因，问使用者 |
