# 开发规范

[English](engineering.md) | 中文

1. 最小充分修改：只改完成任务必需的内容，不顺手修改无关代码。
2. 一次提交一件事：功能、修复、重构尽量分开，便于审查和回退。
3. 职责清晰：一个文件围绕一个职责，一个函数完成一件明确的事。
4. 控制复杂度：减少深层嵌套和重复代码；文件超过 500 行时检查是否需要拆分，行数作为提醒，不是硬限制。
5. 命名和格式统一：名称表达用途，遵循项目现有风格，使用自动格式化工具。
6. 注释说明原因：解释设计意图、限制和特殊处理，并随代码更新。
7. 错误可追踪：不静默吞掉异常，日志提供必要上下文，避免记录敏感信息。
8. 保证安全：校验外部输入，查询参数化，密钥不写进代码仓库。
9. 修改后验证：执行相关检查和测试；修复缺陷时补充有价值的回归测试。
10. 提交前自查：检查差异，清除调试代码、临时文件和无关改动，写清提交目的。
11. 保持文档同步：接口、配置、启动方式变化时更新说明。
12. 适度设计：优先解决当前需求，避免不必要的抽象和依赖。

## 本地检查

先安装 `pip install -e ".[dev]"`，再运行 `ruff check lant tests tools examples`、`ruff format --check lant tests tools examples` 和 `python -m pytest tests --cov=lant`；lint 规则及忽略项的理由写在 `pyproject.toml`。格式化单独提交。用 `python -m build` 构建两种发行物，再在源码树外验证 wheel。CI 运行 lint 和格式检查、Python 3.8/3.10/3.12 上的测试、快速合成算例（到反演工程）以及从安装的 wheel 用包内资源编译 DSurfTomo。
